# Calendar integration rules

- Read `README.md` and the workspace plugin skill before changes.
- Keep local event mutations in the backend domain owner. UI actions, undo, and Workflow use that writer through the SDK.
- Workflow actions own only local native events. Calendar-file occurrences, note dates, and contributed plugin items keep their existing ownership and readonly rules.
- Publish events only after committed document changes, retain scoped host causation, and preserve uncertain outcomes after commit failures.
- A failed event delivery must not undo the success or undo registration of an already committed UI save. Report delivery separately; Workflow actions retain their uncertain-outcome semantics.
- Preserve document revisions and relationships. Verify `tests/domain.test.ts`, `tests/workflow.test.ts`, and affected UI tests without replacing unrelated dirty work.
- Keep integrations behind public SDK contracts, with no app-internal imports or access to another plugin's source or files.

- Notification schedules and completion handling belong to the backend. Calendar/To-Do reminder offsets preserve Off, explicit choices and absolute reminders; date-only items require an explicit time. Persist occurrence recovery before notification and never replay a missed alarm or timer. Pomodoro recovery advances once into a paused phase. The host owns notification audio; UI sound players are for previews only.

- Reminder dataset version changes include explicit additive migrations and an existing-database preservation check; fresh-realm tests alone do not validate rollout.

- Settings → Calendar → Note dates is the twin of Map's Map pins page (17 Nov): keep the two in step. The `dates` settings section declares `"layout": "fill"` (needs a host with `settings-fill`, app 3bb9a668 or later; an older host rejects the key); `NoteDatesSection` is a `.notedate-settings-frame` (`data-plugin-widget-layout="fill"`, pane inset cancelled with `margin: 0 -10px`) holding an SDK `ScrollPanel fill` with the 37px + 1px `settings-listpage-header` bar and master switch in its `header` slot. Below it: one description line, a `.notedate-sources-toolbar` (search, icon-only expand all / collapse all `panel-tool-btn`, Add source with the preset menu; a new source is saved first in the list and opens), then one flat list with a straight edge-to-edge hairline between sources, no cards. Every head is 44px on fixed columns: grip | static disc | name + one-line sub-line (`key = value · folder`, "Whole realm" when unscoped, red `none has a usable “field”` only when notes match but none has a usable date) | count of usable dates | chevron | switch. Opening never changes the head; the name is edited in the editor's Name row; a mouse click leaves no focus box. A source turned off reads "Turned off · rule", is dimmed, counts "–" and has its row switch off and disabled. Zero matches stay a neutral "0 notes found".
- Collapsed sources mount no host-backed fields, colour pickers or action widgets, only the row switch. The open editor is a compact form (132px labels directly followed by the controls, 32px rows, hairlines only between groups): Name; Notes (Folder, Property `[key] = [value]`, status line under it); Date (Property, Format marked invalid when unusable, Repeats `Segmented`, Show count for yearly, Range for repeating, Time start – end plus hint); Entry (Look: icon popover with the icon folder's Open and Refresh, fill and ring `ColorField`s each with a visible clear button beside a set colour; Title `Segmented` plus its property field; Show `ChipsField`); then one footer row with "Use this source" (`Toggle` bound to `!hidden`) and the two-click Delete source. Shared SDK widgets only, never raw inputs. No model or storage change for layout work.
- A kit `Button` is a host widget: its click event's `currentTarget` is no anchor for `api.ui.openMenu` or `openPopover`. Anchor menus on a plugin-owned element (a ref on the button's wrapper), and never gate a control on `:hover` over a host widget, which the plugin document never sees (17 Nov: the preset menu never opened and the colour clear button never appeared).
- The Agenda's Note dates segment is the twin of Map's Map pins tab (18 Nov), in `NoteDateSourceFilterList` (`src/filters.tsx`; the right sidebar has no Note dates tab since 18 Nov): a 38px bar (title, master eye, expand/collapse all, + that opens Settings → Note dates), then one row per used source with usable dates (chevron, white glyph on a disc in the source colour, name, count of usable dates, eye, ⋯ menu with Show only this source and Edit source). Sources without usable dates or turned off in Settings are not listed; Settings keeps their definitions. A source opens to list its dated notes (title, next date); a click reveals that date in Calendar, a double-click opens the note. Rows drag themselves (no grip) and Alt+↑/↓ reorders; reordering swaps only the listed sources. No switches in the sidebar. While open, the Note dates list fills the whole sidebar under the segment bar and the Agenda's search, Groups and day list are hidden (`.agenda-main[hidden]`, kept mounted so the list keeps its scroll listeners). The Sources segment stays an inline list above the Agenda.
- Settings → Calendar has a Notes section with the Note dates switch (18 Nov, like Map's Map pins switch; `noteDatesEnabled`, on by default, pencil to the Note dates page while on). The `dates` section is `visibleWhenSetting: "noteDatesEnabled"`. Off hides that page and the Agenda's Note dates segment, drops the Note dates row from Sources and puts no note date on the calendar (`useCalendarItems` reads no sources); saved sources stay untouched.
- Reminders follow To-Do (18 Nov): Settings → Reminders is Default reminder (Off / Custom) and, for Custom, Time before (hh:mm) as a digits-and-colon field saved on blur or Enter only when valid (at most 168:00). An event's reminder is one select (Plugin default / Off / Custom) with the same hh:mm field, plus the reminder time of day for a date-only event. One offset only: saving a custom time writes `[minutes]`; never bring back the list of minute/hour rows.
- Groups are filtered by the Groups section under the Agenda's search field, drawn and used like Contacts' (18 Nov; `GroupsSection` in `src/filters.tsx`): All entries, groups with subgroups one step in, No group, each with its count (a group's count includes its subgroups). A click shows one group (a group covers its subgroups), the same row again or All entries shows everything, Shift- or ⌘-click adds or removes exactly the clicked group. The title folds the section, names the active filter and carries a clear ×; no Groups icon segment or popover. The selection is saved in the hidden `groupFilter` setting (`calendar:noGroup` = No group) and filters every Calendar surface; a saved `hiddenGroups` list is read as the selection until the first change, which empties it. Folding is saved in `groupsSectionFolded` and `collapsedGroups`.
- The right sidebar (Properties) has three Calendar tabs (18 Nov): Calendar (`calendar.properties`), Groups and Sources; no Note dates tab. Calendar shows the selected entry read-only like To-Do's Task tab (`ItemCard` in `src/surfaces.tsx`): bold title, then a timeline (plain dots without a halo, 20 Nov: dot · start day · start time, a line with the duration, dot · end day · end time; red for an overdue open task; an all-day entry reads All day at its start and counts its days on the line, a one-day entry is one dot), the reminder, the note as written, then source (none for a file entry, whose file card names it), done/open, priority and the group pill (subgroup behind its main group), the place as a link that opens it with To-Do's OpenStreetMap map under it (`src/LocationMap.tsx`; tiles through the backend `map.tile` handler, the package's only network host `tile.openstreetmap.org`, a place without coordinates found through the place search), tags, links and, last, the files; with nothing selected it keeps the period overview, and an entry that no longer resolves reads "This entry is no longer in the calendar", never a raw error. A selected note date resolves from the entry the surface drew, so it keeps its title, colour and fields. Groups is To-Do's Groups tab (`GroupProperties`): dot, name, total and chevron per group, a subgroup one step in, No group last, opening to the counts by source; read-only, in a fill `ScrollPanel`. Sources stays the switch list.
- Footer details and Info rows come from Calendar's `WORKSPACE_DETAILS_V1` provider (18 Nov, `src/details.ts`): Title, Shown period, Selected day, Today, This week, This month, Next, Booked today, Open tasks, Overdue, Events, Note dates this month and Groups (default Title, Today, Next). They count the latest filtered entries a Calendar surface published (`publishCalendarItems` in `useCalendarItems`) and refresh with the time control and every minute; the provider never subscribes to the surface listeners.
- The page ⋯ menu carries Table view (18 Nov), a checked row from the main surface snapshot's `actions` bound to the hidden `tableView` setting. While on, the Calendar page draws `CalendarTable` (`src/CalendarTable.tsx`, modelled on To-Do's main table) instead of the grids: the entries of the shown week, month or year (the switcher and ‹ › still pick the period), one 37px row each under a sticky 37px + 1px header whose columns sort (task check or colour dot, Title, Date, Time, Group pill, Source, Place, Notes; a multi-day entry once with its span). A click only selects the row (the right sidebar shows it), ↑/↓ move the selection, double-click or Enter edits, right-click opens the entry's menu. Narrow panes drop Source, Place and Notes, then Group.
- Every interop contract Calendar provides is declared in `config.json` `provides` (18 Nov: 3.3.28 provided `workspace.details@1.0.0` undeclared and the host refused the whole UI, "does not provide extension"); `tests/plugin.test.ts` checks every provide made at registration against that list.
